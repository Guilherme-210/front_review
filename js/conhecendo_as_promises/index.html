Conhecendo as promessas

📌 Conhecendo as promessas no JavaScript

No JavaScript moderno, Promises é uma ferramenta essencial para lidar com operações assíncronas, como requisições HTTP, leitura de arquivos, timers e muito mais.

Se você já se deparou com callbacks aninhados e o famoso "Callback Hell", saiba que as Promises foram criadas justamente para resolver esse problema, tornando o código assíncrono mais organizado e legível.

🔎 1. O Que é uma Promessa?

Uma Promise (ou "promessa") representa um valor que pode estar disponível agora, no futuro ou nunca .

Ela pode ter três estados

  • Pendente → A promessa foi iniciada, mas ainda não finalizou.
  • Cumprida → A promessa foi concluída com sucesso.
  • Rejeitado → Ocorreu um erro durante a execução.
📜Criando uma Promise Simples 
const minhaPromise = new Promise((resolve, reject) => {
  let sucesso = true; // Altere para false para testar o reject
  
  setTimeout(() => {
    if (sucesso) {
      resolve("✅ Sucesso! A promessa foi resolvida.");
    } else {
      reject("❌ Erro! A promessa foi rejeitada.");
    }
  }, 2000);
});

Explicação:

  • resolve(valor) → Chama o sucesso da Promise.
  • reject(erro) → Chama a bloqueada da Promise

Mas... Como consumimos essa Promessa?

🛠️ 2. Como Usar Promises com .then() e .catch()

Uma Promise pode ser consumida usando os métodos .then() (para sucesso) e .catch() (para erro).

📜 Exemplo Usando .then() e .catch() 
minhaPromise
  .then((mensagem) => {
    console.log(mensagem); // Executa se a Promise for resolvida
  })
  .catch((erro) => {
    console.error(erro); // Executa se a Promise for rejeitada
  });

🔹 Saída no console (caso sucesso = true):

(Depois de 2 segundos...)
✅ Sucesso! A promessa foi resolvida.

🔹 Saída no console (caso sucesso = false):

// (Depois de 2 segundos...)
// ❌ Erro! A promessa foi rejeitada.
⏳ 3. Encadeando Promessas (.then() Aninhado)

Como as promessas são assíncronas, podemos encadear várias delas, garantindo que uma seja realizada após a outra.

📜 Exemplo com Encadeamento 
function primeiraPromise() {
  return new Promise((resolve) => {
    setTimeout(() => resolve("Passo 1 concluído!"), 1000);
  });
}

function segundaPromise(mensagem) {
  return new Promise((resolve) => {
    setTimeout(() => resolve(mensagem + " ➡️ Passo 2 concluído!"), 1000);
  });
}

primeiraPromise()
  .then((resultado) => segundaPromise(resultado))
  .then((resultadoFinal) => console.log(resultadoFinal))
  .catch((erro) => console.error("Erro:", erro));

🔹 Saída sem console:

// (Depois de 2 segundos...)
// Passo 1 concluído! ➡️ Passo 2 concluído!

✔️ O código fica mais organizado do que usando apenas callbacks.

🔄 4. Promise.all() - Executando Múltiplas Promessas ao Mesmo Tempo

Se tivermos várias promessas independentes , podemos Promise.all()usá-las simultaneamente e obter os resultados quando todas forem concluídas .

📜 Exemplo comPromise.all() 
const promessa1 = new Promise((resolve) => setTimeout(() => resolve("🐢 Tarefa 1 concluída"), 3000));
const promessa2 = new Promise((resolve) => setTimeout(() => resolve("🚀 Tarefa 2 concluída"), 2000));
const promessa3 = new Promise((resolve) => setTimeout(() => resolve("💡 Tarefa 3 concluída"), 1000));

Promise.all([promessa1, promessa2, promessa3])
  .then((resultados) => console.log("✅ Todas concluídas:", resultados))
  .catch((erro) => console.error("Erro em alguma promessa:", erro));

Sair no console (após 3 segundos, quando todos terminam):

// ✅ Todas concluídas: ['🐢 Tarefa 1 concluída', '🚀 Tarefa 2 concluída', '💡 Tarefa 3 concluída']

✔️ As Promessas foram realizadas em paralelo, e o resultado só aparece quando TODAS terminam.

⚡ 5. Promise.race() - Pegando a Primeira Promise que Resolver

Se quisermos que apenas a primeira promessa resolvida seja usada , podemos utilizar Promise.race().

📜 Exemplo com Promise.race() 
const promessa1 = new Promise((resolve) => setTimeout(() => resolve("🏆 Primeira a terminar!"), 2000));
const promessa2 = new Promise((resolve) => setTimeout(() => resolve("🔄 Outra promessa"), 3000));

Promise.race([promessa1, promessa2])
  .then((resultado) => console.log("✅ Vencedora:", resultado))
  .catch((erro) => console.error("Erro:", erro));

🔹 Saída no console (após 2 segundos):

// ✅ Vencedora: 🏆 Primeira a terminar!

✔️ Assim que a primeira promessa terminar, as outras serão ignoradas.

🔥 6. Como Usar Promises com async/await(A Forma Moderna)

Uma abordagem ainda mais limpa para lidar com Promises é usando async/await, tornando o código mais próximo do síncrono.

📜 Exemplo com async/await 
function baixarArquivo() {
  return new Promise((resolve) => {
    setTimeout(() => resolve("📂 Arquivo baixado!"), 2000);
  });
}

async function executar() {
  console.log("⏳ Baixando...");
  let resultado = await baixarArquivo();
  console.log(resultado);
}

executar();

🔹 Saída sem console:

// ⏳ Baixando...
// (Depois de 2 segundos...)
// 📂 Arquivo baixado!

✔️ Com async/await, o código fica mais limpo e fácil de entender.

🚨 7. Tratamento de Erros com async/await

Podemos usar try...catch para capturar erros ao usar async/await.

📜 Exemplo com Erro 
function falharDownload() {
  return new Promise((_, reject) => {
    setTimeout(() => reject("❌ Erro no download!"), 2000);
  });
}

async function executar() {
  try {
    console.log("⏳ Tentando baixar...");
    let resultado = await falharDownload();
    console.log(resultado);
  } catch (erro) {
    console.error("⚠️ Falha detectada:", erro);
  }
}

executar();

🔹 Saída sem console:

⏳ Tentando baixar...
(Depois de 2 segundos...)
⚠️ Falha detectada: ❌ Erro no download!

✔️ Com try...catch, o código trata erros de forma clara e segura.

📊 Comparação de Métodos para Trabalhar com Promessas
Método Vantagens Desvantagens
Retornos de chamada Simples e direto, sem novas sintaxes Pode gerar o Callback Hell e dificultar a manutenção
Promessas Evita aninhamento excessivo, facilita o encadeamento Pode ficar prolixo com .then() e .catch()
Promessa.tudo Executa múltiplas promessas em paralelo e retorna todas de uma vez Se uma Promise falhar, todas falham
Promessa.corrida Retorno ao resultado da primeira promessa resolvida Nem sempre é útil, pois ignora o demais
Assíncrono/Aguardando Código mais legível e organizado, parece síncrono Precisa de try...catch para tratar erros
