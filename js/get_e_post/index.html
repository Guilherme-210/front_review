O que são requisições GET e POST?

As requisições GET são um dos tipos de requisições HTTP mais comuns. Elas são usadas para buscar dados de um servidor, como uma API ou um site.

Exemplo simples: Quando você acessa um site no navegador, ele faz uma requisição GET para o servidor para carregar a página.

As requisições POST são usadas para enviar dados para um servidor. Diferente de GET, que só busca informações, POST é usado para criar ou modificar recursos no servidor.

Exemplo comum: Quando você preenche um formulário e clica em "Enviar", seu navegador provavelmente faz uma requisição POST com os dados do formulário.
📌 Características do GET e POST

🔹 Características da requisição GET

  • Usada para buscar dados – não deve ser usada para enviar ou modificar dados.
  • Os parâmetros são passados na URL – isso significa que os dados são visíveis.
  • Pode ser armazenada em cache – otimiza desempenho ao evitar múltiplas chamadas ao servidor.
  • Pode ser salva no histórico do navegador – pois os dados ficam na URL.
  • Não altera o servidor – apenas lê informações.

🔹 Características da requisição POST

  • Usada para enviar e salvar dados – cria ou modifica informações no servidor.
  • Os dados são enviados no corpo da requisição – ao invés da URL.
  • Mais seguro que GET – porque os dados não aparecem na URL.
  • Não é armazenada em cache – evita envio duplicado acidental.
  • Não pode ser salva no histórico do navegador – porque os dados não ficam visíveis na URL.
🔹 Exemplo prático: Fazendo uma requisição GET

🖥️ 1. No navegador (URL)

Se você acessar:

local ou arquivo 
https://jsonplaceholder.typicode.com/posts

Isso faz uma requisição GET e retorna uma lista de posts (dados fictícios de uma API de teste).

🛠️ 2. Com JavaScript (Fetch API)

O método fetch() permite fazer requisições GET de forma simples:

local ou arquivo 
fetch("https://jsonplaceholder.typicode.com/posts")
  .then(response => response.json()) // Converte a resposta para JSON
  .then(data => console.log(data))  // Exibe os dados no console
  .catch(error => console.error("Erro na requisição:", error));

🔹 Aqui, estamos buscando uma lista de posts e exibindo no console.

📩 3. GET com parâmetros na URL

Exemplo: buscar um post específico (id = 1):

Podemos enviar parâmetros para o servidor na própria URL.

📜 Exemplo:
js 
fetch("https://jsonplaceholder.typicode.com/posts/1")
  .then(response => response.json())
  .then(data => console.log(data));

💡 Os parâmetros também podem ser passados na URL usando ? e &:

js 
fetch("https://api.exemplo.com/users?nome=João&idade=25");

Isso enviaria nome=João e idade=25 para o servidor.

🔹 Exemplo prático: Fazendo uma requisição POST

🛠️ 1. Com JavaScript (Fetch API)

Podemos usar fetch() para enviar dados com POST:

local ou arquivo 
fetch("https://jsonplaceholder.typicode.com/posts", {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    title: "Novo Post",
    body: "Conteúdo do post...",
    userId: 1
  })
})
  .then(response => response.json()) // Converte a resposta para JSON
  .then(data => console.log("Resposta do servidor:", data))
  .catch(error => console.error("Erro na requisição:", error));

🔍 O que está acontecendo aqui?

  • method: "POST" → Define que estamos enviando dados.
  • headers: { "Content-Type": "application/json" } → Indica que os dados são JSON.
  • body: JSON.stringify({...}) → Converte o objeto para JSON antes de enviar.

💡 Dica: O servidor pode responder com o objeto salvo e um id gerado automaticamente.

📩 Enviando dados no corpo da requisição

Diferente de GET, onde os parâmetros vão na URL, no POST os dados são enviados dentro do corpo da requisição (body).

Isso deixa a requisição mais segura e permite enviar grandes volumes de dados

📜 Exemplo de envio de formulário com fetch():
local ou arquivo 
fetch("https://api.exemplo.com/contato", {
  method: "POST",
  body: new FormData(document.querySelector("form"))
});

Aqui, usamos FormData para enviar os dados do formulário automaticamente.

🔹 GET e POST no Axios (Alternativa ao Fetch)

O axios é uma biblioteca popular para requisições HTTP. Exemplo de um GET:

js 
axios.get("https://jsonplaceholder.typicode.com/posts")
  .then(response => console.log(response.data))
  .catch(error => console.error("Erro na requisição:", error));

O axios simplifica as requisições POST:

js 
axios.post("https://jsonplaceholder.typicode.com/posts", {
  title: "Novo Post",
  body: "Conteúdo do post...",
  userId: 1
})
  .then(response => console.log("Resposta do servidor:", response.data))
  .catch(error => console.error("Erro na requisição:", error));

🔹 GET no Axios (Alternativa ao Fetch)

  • Mais fácil de usar que fetch()
  • Já converte resposta para JSON automaticamente

🔹 POST no Axios (Alternativa ao Fetch)

  • Mais fácil de usar que fetch()
  • Já converte resposta para JSON automaticamente
🔹 GET vs POST: Qual a diferença?
Característica GET POST
Uso principal Buscar dados Enviar dados
Parâmetros Na URL (?chave=valor) No corpo da requisição
Segurança Menos seguro (dados visíveis na URL) Mais seguro (dados ocultos no body)
Cacheável? Sim Não
Tamanho da requisição Limitado pela URL Pode enviar grandes volumes de dados

Se precisar enviar dados sigilosos ou modificar o servidor, não use GET, use POST! 🚀

Se precisar buscar informações, use GET. Se precisar enviar dados ou modificar o servidor, use POST! 🚀

🚀 Resumo rápido GET

  • GET serve para buscar dados.
  • Os parâmetros são enviados na URL.
  • Pode ser testado direto no navegador.
  • Melhor para dados públicos, não sensíveis.
  • Pode ser feito com fetch() ou axios.

🚀 Resumo rápido POST

  • POST é usado para enviar e salvar dados no servidor.
  • Os dados são enviados no corpo da requisição, não na URL.
  • Mais seguro que GET, ideal para informações sensíveis.
  • Pode ser feito com fetch() ou axios.
  • Não deve ser armazenado em cache para evitar reenvios acidentais.
