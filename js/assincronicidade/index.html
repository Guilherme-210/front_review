Assincronicidade no JavaScript

o que e Assincronicidade no JavaScript

O JavaScript é single-threaded, ou seja, executa apenas uma instrução por vez na thread principal. No entanto, ele permite operações assíncronas, que ocorrem em segundo plano sem bloquear a execução do restante do código. Isso é essencial para lidar com tarefas demoradas, como requisições de APIs, leitura de arquivos, timers(setTimeout) e muito mais.

📌 1. O que é Código Síncrono e Assíncrono?

🕹️ Código Síncrono (Executa Passo a Passo)

No código síncrono, cada linha de código precisa esperar que a anterior seja concluída antes de executar.

📜 Exemplo: 
console.log("Início");
console.log("Processando...");
console.log("Fim");

🔹 Saída:

// Início
// Processando...
// Fim

✔️ Aqui, cada comando bloqueia a execução até que seja finalizado.

🔄 Código Assíncrono (Executa em Paralelo)

No código assíncrono, certas tarefas podem ser delegadas para serem processadas enquanto o restante do código continua sendo executado.

📜 Exemplo: 
console.log("Início");

setTimeout(() => {
  console.log("Executado após 2 segundos ⏳");
}, 2000);

console.log("Fim");

🔹 Saída:

Início
Fim
(Depois de 2 segundos...)
Executado após 2 segundos

✔️ O setTimeout() é assíncrono, então o código não precisa esperar por ele.

⚙️ 2. Event Loop e Callbacks: Como Funciona?

O Event Loop gerencia a execução do código assíncrono sem JavaScript. Ele monitora a Pilha de Chamadas (pilha de execução) e a Fila de Tarefas (fila de tarefas) para garantir que as funções assíncronas sejam executadas no momento certo.

Fluxo básico:

  1. O código síncrono é executado primeiro.
  2. Tarefas assíncronas (como setTimeout(), fetch(), eventos) são enviadas para a Task Queue.
  3. Quando uma Call Stack está vazia, o Event Loop pega as tarefas da Task Queue e as executa.
📜 Exemplo para entender o Event Loop 
console.log("A");

setTimeout(() => {
  console.log("B");
}, 0);

console.log("C");

🔹 Saída sem console:

// A
// C
// B

Mesmo com setTimeout(..., 0), "B" não é impresso antes de "C", pois a função vai para a Task Queue, aguardando o Event Loop liberar a execução.

📞 3. Retornos de chamada: A Primeira Solução

Antes da introdução de Promises e async/await, a forma tradicional de trabalhar com código assíncrono era através de callbacks (funções passadas como argumento para serem executadas depois).

📜 Exemplo de retorno de chamada 
function baixarArquivo(url, callback) {
  console.log(`Baixando arquivo de ${url}...`);

  setTimeout(() => {
    console.log("Download concluído! ✅");
    callback("Arquivo salvo!");
  }, 2000);
}

baixarArquivo("https://meuarquivo.com", (mensagem) => {
  console.log(mensagem);
});

🔹 Saída sem console:

// Baixando arquivo de https://meuarquivo.com...
// (Depois de 2 segundos...)
// Download concluído! ✅
// Arquivo salvo!

✔️ A função callbacké executada somente após o download ser concluído .

❌ Problema dos Callbacks: Callback Hell
📜 Exemplo:

O uso excessivo de callbacks pode tornar o código difícil de entender e manter, gerando o "Callback Hell". 

buscarDados((dados) => {
  processarDados(dados, (resultado) => {
    salvarNoBanco(resultado, (resposta) => {
      console.log("Dados salvos!", resposta);
    });
  });
});

Problema: O código fica aninhado demais e difícil de manter.

🔮 4. Promessas: Melhorando a Assincronicidade

Uma Promessa (promessa) representa uma operação que será resolvida no futuro. Ela pode ter três estados:

  • Pendente (Pendente) → A operação ainda não foi concluída.
  • Cumprida (Resolvida) → A operação foi concluída com sucesso.
  • Rejeitado (Rejeitada) → Ocorreu um erro na operação.
📜 Criando uma Promessa 
function baixarArquivo(url) {
  return new Promise((resolve, reject) => {
    console.log(`Baixando arquivo de ${url}...`);

    setTimeout(() => {
      let sucesso = true;
      if (sucesso) {
        resolve("Download concluído! ✅");
      } else {
        reject("Erro no download! ❌");
      }
    }, 2000);
  });
}

baixarArquivo("https://meuarquivo.com")
  .then((mensagem) => console.log(mensagem)) // Sucesso
  .catch((erro) => console.error(erro)); // Erro

🔹 Saída sem console:

Baixando arquivo de https://meuarquivo.com...
(Depois de 2 segundos...)
Download concluído! ✅

✔️ Vantagens das Promessas:

  • Código mais organizado e legível.
  • Evite o Callback Hell.
  • Fácil encadear operações (.then()).
⏳ 5. Async/Await: Uma Solução Moderna

O async/awaitfacilita o uso de código assíncrono de maneira mais síncrona e legível .

📜 Usandoa sync/await: 
function baixarArquivo() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve("Download concluído! ✅");
    }, 2000);
  });
}

async function executar() {
  console.log("Baixando arquivo...");
  let mensagem = await baixarArquivo();
  console.log(mensagem);
}

executar();

🔹 Saída:

// Baixando arquivo...
// (Depois de 2 segundos...)
// Download concluído! ✅

✔️ Vantagens de async/await:

  • Código mais legível e limpo.
  • Evita .then() encadeados.
  • Se comporta como código síncrono, mas continua sendo assíncrono.
⚠️ 6. Tratando Erros com try...catch

Podemos capturar erros em funções async com try...catch.

📜 Exemplo: Tratamento de Erros 
function baixarArquivo() {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      let sucesso = false;
      if (sucesso) {
        resolve("Download concluído! ✅");
      } else {
        reject("Erro no download! ❌");
      }
    }, 2000);
  });
}

async function executar() {
  try {
    console.log("Baixando arquivo...");
    let mensagem = await baixarArquivo();
    console.log(mensagem);
  } catch (erro) {
    console.error("Falha:", erro);
  }
}

executar();

🔹 Saída sem console:

// Baixando arquivo...
// (Depois de 2 segundos...)
// Falha: Erro no download! ❌

✔️torna try...catcho tratamento de erros mais simples e elegante.
